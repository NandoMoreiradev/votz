# Primeira rodada de QA no Android físico

Data: 17/11/2026. Aparelho: Realme RMX3840, conectado por ADB/USB. Aplicativo: development build `br.com.votz.app`, Expo SDK 58, com Metro local na porta 8081 e API local na porta 3000.

Conta utilizada: `demo.cidadao1@votz.test` (Ana Cidadã Demo), conforme [dados de demonstração](README-dados-de-teste.md). Testes executados por toques e digitação no aparelho, com inspeção visual das telas e consulta aos logs do processo do Votz.

## Resultados observados

| Fluxo exercitado | Resultado |
| --- | --- |
| Alternar publicações e relatos | Listas carregaram com os dados locais. |
| Abrir detalhe de publicação | Texto, enquete e área de comentários exibidos. |
| Abrir detalhe de relato | Descrição, status, contadores e memória pública exibidos. |
| Apoiar sem login | Encaminhou para a tela de login. |
| Explorar políticos e abrir perfil | Perfil e estados vazios exibidos. |
| Buscar entidades sem resultados e limpar busca | Mensagem de nenhum perfil encontrado; lista voltou ao limpar o termo. |
| Abrir entidade e um relato direcionado a ela | Perfil do Hospital das Clínicas e detalhe do relato abriram. |
| Login de cidadão demo | Login concluído e conta exibida na aba Perfil. |
| Adicionar e retirar apoio | Contador de um relato existente passou de 2 para 3 e retornou a 2. |
| Seguir e deixar de seguir entidade | Botão passou a “Deixar de seguir” e retornou ao estado anterior. |
| Criar publicação de texto pelo Android | Publicação criada e detalhe aberto. |
| Comentar e curtir a publicação criada | Comentário apareceu; contadores exibiram uma curtida e um comentário. |
| Criar relato de texto, categoria Outro | Relato criado com status Aberto e evento inicial na memória. |
| Encerrar processo e reabrir app | Sessão recuperada sem redigitar credenciais; conta demo confirmada na aba Perfil. |
| Abrir perfil público do cidadão conectado | Publicações exibidas, incluindo o conteúdo de QA criado nesta rodada. |

Nenhuma falha bloqueante observada nesses fluxos. Isso não equivale a aprovação completa para produção ou medição de desempenho em release.

## Ajuste realizado

Corrigido o singular/plural dos contadores de apoios, comentários, curtidas e votos, inclusive nos rótulos de acessibilidade. Conferido no aparelho e verificado com lint e TypeScript, ambos aprovados.

Melhoria de usabilidade observada para próxima iteração: o botão do relato permanece com o texto “Apoiar / retirar apoio”; deve passar a indicar claramente o estado do apoio do usuário.

## Dados criados

Foram mantidos dois registros claramente identificados para inspeção manual:

- Publicação: `QA mobile USB 20261117-01. Publicacao criada no Android para validar o fluxo.`, com uma curtida e um comentário de QA.
- Relato: `QA mobile USB 20261117-01 - relato de teste`, categoria Outro, com descrição informando que não representa um problema real.

O apoio e o acompanhamento feitos em registros existentes foram revertidos durante o teste. O aplicativo ficou conectado à conta demo para continuar a exploração.

## Fora desta rodada

Upload e seleção de fotos, câmera, localização/permissões, MFA, troca de contexto institucional, logout/revogação, votação efetiva em enquete, paginação extensa, falhas de rede, acessibilidade assistiva, notificações, iOS e desempenho de uma build release ainda precisam de validações específicas.
